1. Introduction

In traditional software development, engineers manually execute tests on local machines, copy files across environments, and configure runtime dependencies individually. This manual workflow often causes configuration drift (the classic "it works on my machine" issue), slows down software releases, and introduces human errors during deployment.

Containerization solves environment consistency by bundling source code, dependencies, and runtime libraries into portable Docker images. Combining containers with Continuous Integration and Continuous Deployment (CI/CD) removes manual handoffs entirely. This project implements a complete, end-to-end CI/CD pipeline for a Node.js web application using GitHub Actions, Docker, and Docker Hub, running locally via Docker Compose without requiring paid cloud infrastructure.

2. Abstract

This project demonstrates an automated software delivery lifecycle built strictly with free and open-source DevOps tooling. Whenever a developer pushes code changes to the main branch of the GitHub repository, an event-driven GitHub Actions workflow (.github/workflows/ci-cd.yml) automatically initiates two sequential jobs. First, the test job sets up a Node.js 20 environment, installs dependencies, and runs an automated HTTP verification suite (test.js). Second, upon test success, the build-and-push job securely logs into Docker Hub using encrypted repository secrets, builds an optimized Alpine-based Docker container image, and publishes the vaishnaviiwarad/cicd-demo-app:latest image. Finally, the verified container image is pulled and deployed locally via Docker Compose, serving a live status dashboard on port 3000.

4. Steps Involved in Building the Project

Step 1: Application & Automated Test Development

Created a lightweight Express web application (app.js) serving a styled deployment status page at / (showing app name, version, container hostname, and live status) and a JSON health endpoint at /health. Implemented automated tests in test.js using Node's native http and assert modules to confirm both endpoints return HTTP 200 OK before container packaging.

Step 2: Containerization with Dockerfile & Docker Compose

Wrote a Dockerfile using the lightweight node:20-alpine base image, copying package.json, running npm install --omit=dev, exposing port 3000, and setting CMD ["node", "app.js"]. Configured docker-compose.yml to reference vaishnaviiwarad/cicd-demo-app:latest with port mapping 3000:3000 and restart: unless-stopped, alongside k8s-deployment.yaml for optional Minikube deployment.

Step 3: Securing Registry Credentials with GitHub Secrets

Generated a Docker Hub Personal Access Token (PAT) with Repo Read & Write permissions and stored both DOCKERHUB_USERNAME (vaishnaviiwarad) and DOCKERHUB_TOKEN inside GitHub Encrypted Repository Secrets. This ensures authentication credentials are encrypted at rest and masked in CI/CD logs without exposing secrets in code.

Step 4: Configuring GitHub Actions CI/CD Workflow

Authored .github/workflows/ci-cd.yml triggered on push and pull_request to main. Job 1 (test) runs npm install and npm test on an ubuntu-latest runner. Job 2 (build-and-push) depends on Job 1 (needs: test) and only executes on pushes to main, authenticating via docker/login-action@v3, building the image, and pushing vaishnaviiwarad/cicd-demo-app:latest to Docker Hub.

Step 5: Local Container Deployment & End-to-End Verification

Pushed the repository to GitHub (git push -u origin main) and verified both CI/CD workflow jobs completed with green checkmarks. Confirmed the published image on Docker Hub, then pulled and started the container locally on Docker Desktop using docker compose pull and docker compose up -d.

  • GitHub Actions Pipeline: Automated Run Tests and Build & Push Docker Image jobs succeeded on push to main.

5. Conclusion

This project successfully demonstrates how to design, automate, and verify a complete CI/CD pipeline using GitHub Actions, Docker, and Docker Hub without requiring any paid cloud servers. By enforcing automated unit tests before image creation, securing registry tokens via encrypted secrets, and enabling single-command local deployment with Docker Compose, the workflow eliminates manual errors, prevents environment inconsistencies, and delivers fast, repeatable deployments on every code commit.
